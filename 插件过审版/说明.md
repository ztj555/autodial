## 一、为什么要单独做一份

原版按现状提交会被卡审核，问题不在格式（Edge 用的就是 Chromium MV3，Chrome 扩展不用改就能跑），
而在**权限口径**和**隐私合规**。这次只改这两件事，**功能行为一行没变**。

| # | 改动 | 原来 | 现在 | 为什么 |
|---|---|---|---|---|
| 1 | **撤掉 `<all_urls>`** | `host_permissions` 里有 `<all_urls>` | 12 条精确白名单 | `<all_urls>` 配一个"拨号助手"是**拒稿高发项**，审核讲最小权限 |
| 2 | **自定义地址改运行时授权** | 靠 `<all_urls>` 兜底 | `optional_host_permissions` + `chrome.permissions.request` | 保留"用户自己填服务器"的能力，但只在用户**点保存那一刻**申请，正常使用碰不到 |
| 3 | **地址池源站加白名单** | 被 `<all_urls>` 覆盖 | 显式列出 Gist / Gitee / `raw.giteeusercontent.com` | ⚠️ Gitee 现在会 **302 跳到 `raw.giteeusercontent.com`**，漏了这条「从网络获取」会静默失效 |
| 4 | **精简 permissions** | `activeTab`、`clipboardWrite`、`alarms`、`contextMenus`、`storage` | 只留 `storage`、`alarms` | 实测代码里 `activeTab`/`clipboardWrite`/`contextMenus` **根本没被用到**，留着只会增加审核阻力 |
| 5 | **剔除内部文件** | 含 `README.md`、`AutoDial-API.md`、`create-icons.ps1` | 已剔除 | README 会暴露内部实现、Gist 地址；这三个文件对运行毫无用处 |
| 6 | **名称/描述改成对外口径** | `AutoDial` / `…（PIN整合版）` | `AutoDial 一键拨号助手` / 见下 | "PIN整合版"是内部黑话，审核员看不懂 |
| 7 | **自动选服务器加了护栏** | 候选池直接取第 1 个 | `pickAuto()` 跳过未授权主机 | 撤掉 `<all_urls>` 后，若地址池新增了没见过的服务器，自动切过去会**所有请求静默失败** |

`addr.js` 里新增的 `STATIC_ORIGINS` 常量**必须与 manifest 的 `host_permissions` 保持一致**，
以后加服务器两个地方都要改（已在代码注释里标明）。

## 四、你还需要做 4 件事（我做不了的部分）

1. **开发者账号** — Microsoft 账号入驻 Partner Center 的 Edge 计划，**免费**。
   - 🔴 **登录用的微软账号，官方定义的 MSA 是 `@outlook.com` / `@live.com` / `@hotmail.com`** ——
     微软官方文档把 MSA 直接定义为「An Outlook.com, Live.com, or Hotmail.com account」。用 QQ / 163 / Gmail
     这类邮箱注册的微软账号属于**非标准**情形。
     👉 **若注册已被拦，推荐改走「GitHub 登录」**（官方支持的路径，微软会自动替你创建一个标准 MSA 并绑定）。
     步骤见 `提交材料/06-注册被封锁-处置与申诉.md` 第五节第 2 步。（表单里那个「联系人邮箱」随你填）
   - ✅ 「州/省份」是**下拉框，选「浙江」就行**（别手打）。网上流传「要填代码 `ZJ`」，已逐字核对官方文档**无此要求**；若「验证地址」报错再改成 `ZJ` 重试。
   - ⚠️ **发布者显示名称注册后极难改**（改会触发重新验证，需联系支持，官方文档甚至写「可能要开新号」）⇒ 点「接受并继续」之前定死。
   - ⚠️ **账户类型（个人/公司）和账户国家地区提交后都不能改**。
     建议选**个人**：验证通常几小时；选公司要几天到几周，还可能接到微软验证电话。
   - 🔴 **当前卡点：点「接受并继续」后被微软的自动信任审核拦下**（页面上参考编号 `715-123225`）。
     **这不是你表单填错了** —— 2026 年 7 月起全球开发者都在撞同一个页面。处置流程见
     **`提交材料/06-注册被封锁-处置与申诉.md`** 或手册 **1.6 节**：含四步处置、可复制的英文申诉邮件。
     **申诉走两条**：① GitHub Issue（官方文档把「咨询 Partner Center 开发者账号」列为 Issues 页的正当用途）
     ② 邮件 `ext_dev_support@microsoft.com` —— **HAR 文件只能走这条**（含你的登录凭据）。
     （Partner Center 里开不出工单，因为没有 workspace。）
2. **隐私政策 URL** — 把 `提交材料/01-隐私政策.html` 挂到一个**公开可打开的地址**。
   先搜索「必须替换」，把那一处邮箱改成你能长期收信的邮箱，其余信息已填好。
   推荐用 GitHub Pages（你有账号），手册第 2 步有逐步操作。
   ⚠️ 空壳链接、需要登录才能看的链接，都会被拒。
3. **决定要不要给审核员 CRM 测试账号** —— 见 `03-审核员测试说明.md`。
   - 给 → 过审概率明显更高
   - 不给 → 建议补一段 1 分钟演示视频（比开放账号更可控）
4. **点提交** —— 上传包、填完表单、贴好认证说明，点「发布」。这步只能你自己做。

## 六、重新打包（改完代码后）

`dist/AutoDial-6.4.0.zip` 已生成。**改完代码要重新打**，注意两点：

- **zip 根目录直接放 `manifest.json`**，不要再套一层文件夹，否则商店会拒
- 别把 `提交材料/`、`说明.md` 打进包里

```powershell
# 在 插件过审版 目录下执行（PowerShell）
Remove-Item dist\AutoDial-6.4.0.zip -ErrorAction SilentlyContinue
Compress-Archive -Path extension\* -DestinationPath dist\AutoDial-6.4.0.zip
```

打完后自检（应为 20 个文件、根目录有 manifest.json）：
```bash
unzip -l dist/AutoDial-6.4.0.zip | head -30
```

## 七、发版预期（先说清楚）

- 第一次提交**被拒的概率不低**，主因大概率是"审核员无法完整验证 CRM 部分"
- 但**注册免费、提交免费、被拒可以改完重提**，被拒会告诉你具体原因 —— 先试一次是最划算的
- 上架走 **Hidden（隐藏）发布**：不进搜索、别人搜不到，只有拿到你链接的人能装；
  URL 和扩展 ID 在 Hidden 与 Public 之间**不变**，以后想公开不用重做
- 代价：**每次发版要重走审核**，官方说明为「认证过程最多可能需要 **七个工作日**」。这是这条路唯一的价格
