## 一、症状

点「接受并继续」后跳到这个地址：

```
https://partner.microsoft.com/en-us/dashboard/account/exp/enrollnow/error/msedgeaddons/SessionValidationFailed
```

页面显示：

> Microsoft 是建立在信任基础上的。我们采用严格的评估和认证流程；结果你的请求被封锁了。
> 参考编号：**715-123225**

**一句话结论：这不是你表单填错了。** 这是微软的**自动信任审核**把这一次会话拦下了。2026 年 7 月起，西班牙、捷克、中国的开发者都在报同一个页面，**参考编号完全一样**（微软 Q&A 与官方 GitHub 仓库 `microsoft/MicrosoftEdge-Extensions` 上可查）。

## 二、三个编号的区别（申诉时别搞混）

| 页面上的东西 | 是什么 |
|---|---|
| 参考编号 `715-123225` | **系统的固定分类码，不是你个人的编号**。全球所有报告里都是这个数。申诉照抄，但它定位不到你这次尝试 |
| 相关性 ID（如 `F804E162-…`） | **你这次尝试的唯一编号，申诉必须带**。每次重试都会变 ⇒ **每失败一次就截一张图存档** |
| 事务编号 | 你这次那栏是**空的**，不用管 |

> URL 里那个 `SessionValidationFailed` 是「**会话**校验失败」，不是「资料不合格」—— 说明卡在设备/会话的可信度校验，还没走到审你资料那一步。

## 三、诊断依据（本机实测，可作为佐证发给微软）

`vlscppe.microsoft.com` 是微软用来做设备 / 会话风控校验的端点。

```
【正常可达】（家庭宽带下复核，2026-09-18 18:16）
  partner.microsoft.com      HTTP 200  ✓
  login.live.com             HTTP 200  ✓
  go.microsoft.com           HTTP 200  ✓

【被强制重置】
  vlscppe.microsoft.com      ✗ WinError 10054 远程主机强迫关闭连接
```

复现细节：

- 真实 Edge（隔离 profile）打开 → 「嗯… 无法访问此页面 / 已重置连接」
- `curl` 与 `openssl` 直连该 IP 的 443 端口同样被重置
- **连「不带域名（不带 SNI）」的连接也被重置** ⇒ 是这条网络到该地址不通，**换 DNS 无效**
- 同一台机器、同一时刻，其它微软域名全部正常
- DNS 解析正常（`192.225.158.103`，不是被劫持到假 IP）
- 本机系统代理未设置、未发现 VPN 虚拟网卡

> **可信度说明**：微软**没有**公开承认「这个域名不通 ⇒ 注册必被拒」。所以这是**高度可疑**，不是铁证。
> 它值得先试，是因为**成本只有几分钟**，不是因为它一定有效。

## 四、换邮箱 / 换账号能解决吗？先看公开案例

微软官方问答里，围绕编号 `715-123225` 的两份公开报告指向**不同方向**：

| 案例 | 登录邮箱 | 结果 / 它说明什么 |
|---|---|---|
| 中国开发者、个人账号（2026 年） | `******@163.com` | 被拦。**和你几乎一模一样的组合**（国内邮箱 + 中国 + 个人 + 同一编号） |
| 个人账号（2026-08-19） | 纯 `@outlook.com` | **照样被拦** ⇒ 换成微软域邮箱**也不保证能过** |

**结论：换账号 / 换邮箱不是万灵药。** 被拦的本质是**自动信任审核** —— 对设备、网络、身份做综合判断，不是某一个字段填错。

所以：**自助动作值得先试**（便宜、几分钟），**但别抱太高期望**；这个编号全球一致，本身就是系统性问题，真要解决通常得靠第五节第 4 步的**人工复核**。

官方给过一条明确建议，而你正好符合：**「避免使用 VPN 或代理，用正常的住宅网络连接」** —— 家庭宽带没问题。

## 五、处置四步（按顺序，一步别跳）

### 第 1 步 · 换一条网络

- 用**手机热点**（4G / 5G 流量）让电脑上网
- 你现在是**家庭宽带** —— 这本身已符合官方要求的「正常住宅网络」，但这条线实测连不上风控端点 ⇒ 要换的是**运营商和路由**，手机热点是最快的换法
- 把电脑上的 **VPN / 代理 / 加速器 / 安全软件**（Clash、360、火绒等）**全部关掉**
- 连上热点后跑一次自检脚本（见第九节），确认 `vlscppe.microsoft.com` 通了再去注册

### 第 2 步 · 改用 GitHub 账号登录（官方支持的路径）

**为什么走这条**：官方文档把 MSA 定义为「An Outlook.com, Live.com, or Hotmail.com account」，而 GitHub 登录这条路，微软写着「**Microsoft account (MSA) will be created for you automatically if necessary**」—— 它会替你建一个标准域的账号并绑定。你已经有 GitHub 账号 `ztj555`。

步骤：

1. 打开 Partner Center 登录页 <https://partner.microsoft.com/dashboard/microsoftedge/public/login>
2. 页面**底部**点「Sign-in options / 登录选项」
3. 选「**Sign in with GitHub**」
4. 输入 GitHub 账号（`ztj555`）
5. 点「**Authorize Microsoft-corp**」授权
6. 回到注册表单继续填（字段填法见《上架操作手册》1.3）

> ⚠️ 只支持**个人** GitHub 账号，工作账号不支持。
> ⚠️ 区分两个邮箱：**登录身份**用哪个账号；表单里那个「联系人邮箱」随你填（可以继续用 QQ 邮箱收通知）。

### 第 3 步 · 用干净会话，只试一次

1. 关掉 Edge **全部窗口**
2. `Ctrl+Shift+N` 开一个 **InPrivate 无痕窗口**
3. **只登录这一个账号**（别同时登别的）
4. 用官方深链进注册：<https://go.microsoft.com/fwlink/?linkid=2099798&ref=pcp>
5. ⚠️ 无痕窗口默认不加载扩展 —— 这正好。你平时装的那些扩展（尤其广告拦截 / 隐私类）会拦掉微软的校验脚本

### 第 4 步 · 还是被拦 → 走官方渠道，两条一起用

🔴 **不要去 Partner Center 里找工作单，那条路是死的**：官方工单表单要求先选一个「工作区 / Workspace」，而你没有任何已注册程序、列表是空的，工单**根本开不出来**。

**① 开一个 GitHub Issue（建议先做这条）**

## 六、HAR 文件怎么抓（照抄微软团队自己写的步骤）

1. 打开 Edge，**先按 `Ctrl+Shift+N` 开无痕窗口**（HAR 里带着 cookie，无痕最安全）
2. 在无痕窗口里**从头走一遍注册流程**，直到那个封锁页面出现
3. 按 `F12` 打开开发者工具 → 切到 **「网络 / Network」**标签
4. 确认左上角的**录制按钮是红色（正在录）**
5. 点 **「清除 / Clear」**，把已有记录清空
6. **从出错那一步重新操作一遍**（比如再点一次「接受并继续」）
7. 封锁页面出现后，点 **「导出 HAR / Export HAR」** 下载按钮，存成 `.har` 文件
8. ⚠️ **导出之前不要关掉这个标签页**，否则抓不到

> 🔴 HAR 里含你的登录凭据。**只发给上面那个邮箱**，不要贴到公开论坛、GitHub issue 或问答网站。

## 八、四件千万不要做的事

1. **不要反复注册新账号**去绕过 —— 微软官方问答里明确警告：这会让后续验证变得更难
2. **不要对着「接受并继续」猛刷** —— 换网络 / 换会话后**只试一次**；每次失败留一组编号，刷只会污染记录
3. **不要改账号类型 / 地区**去重来 —— 这两栏注册后改不了，乱改可能把账号搞成半成品
4. **别把这页当成「我资料不合格」**而反复改地址电话 —— 问题不在那里
