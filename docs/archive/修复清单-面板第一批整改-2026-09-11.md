# 云端管理面板 · 第一批整改变更清单

日期：2026-09-11
改动文件：`cloud-relay/python/dashboard.html`、`cloud-relay/python/cloud_relay_v2.py`
备份位置：`.workbuddy/backup/2026-09-11-1541/`（原始 MD5：dashboard.html `48be8c1b…`、cloud_relay_v2.py `6d405dbc…`）
目标：解决"看起来正常、其实没连上 / 没保存 / 没导全"的**状态可信度**问题

## 一、改动明细（8 项）

### 1. 统一请求层：请求失败不再被静默吞掉
**文件**：`dashboard.html` · `apiGet()` / 新增 `setApiBanner()`
**改前**：`try { fetch…return r.json() } catch(e) { return null }` —— 失败一律返回 `null`，各页把 `null` 渲染成"暂无数据"。分不清"真的没数据"和"接口坏了"。
**改后**：
- 新增页面顶部全局横幅 `#api-banner`（红底 + 图标 + 操作按钮）；
- `401` → 清除本地 token + 横幅提示"登录已过期"+「重新登录」按钮；
- `429` → 横幅提示"请求过于频繁，已被限流"（此前限流只体现在日志里，前端无感）；
- 其它非 2xx → 横幅显示具体 HTTP 状态码；
- 网络异常 → 横幅提示"无法连接到服务器"；
- 请求成功自动收起横幅（且只在已显示时才操作 DOM，无多余重排）。

### 2. 补上三处静默 `catch{}`（并补成功反馈）
**文件**：`dashboard.html` · `setDeviceLabel()` / `setPinGroup()` / `setAdvisorName()` / `setDeviceDefaultPin()`
**改前**：`catch(e) { /* 静默失败 */ }` —— 内联编辑保存失败时界面毫无反应，刷新后打回原形，用户以为已存。
**改后**：失败 → `toast` 明确报错；分组/姓名失败时 `loadPins()` 重新拉取，保证**界面显示 = 服务端真实值**；成功 → 轻量提示"已保存"。

### 3. 删除假的"保存设置"
**文件**：`dashboard.html` · 设置页 + `saveSettings()`
**改前**：`saveSettings()` 不发任何请求，只弹一句"设置已保存提示"——改了端口/日志级别以为生效，实际进程仍按旧参数跑。
**改后**：移除该函数与按钮；端口改为**只读**并显示真实运行端口（由新增 `refreshSettingsInfo()` 走 `/api/status` 拉取）；日志级别只读；下方给出明确指引（需在服务器端修改 Supervisor 启动参数后重启）。

### 4. 通话记录导出对齐（新增后端接口）
**文件**：`cloud_relay_v2.py` 新增 `/api/v1/calls/export`；`dashboard.html` · `exportCallsCSV()`
**改前**：前端拼 CSV，**只导当前页 50 行**，且无任何提示——年底对账会静默缺数据。
**改后**：
- 后端新增 `/api/v1/calls/export`，支持 `device_id / pin / date_from / date_to / number` 同一套筛选条件，`LIMIT 200000`，admin token 鉴权，BOM 头防 Excel 乱码，含 CSV 公式注入防护（与 `visits/export` 完全一致的实现风格）；
- 前端改为服务端导出，文案提示"已按当前筛选条件导出全部匹配记录"。

### 5. 数据表横向滚动（窄屏不再压变形）
**文件**：`dashboard.html` · CSS + 新增 `wrapDataTables()`
**改前**：8 张 `data-table` 无横向滚动容器，10~11 列在窄屏被极限压缩、文字换行错位。
**改后**：页面加载时自动为所有 `data-table` 包裹 `.table-wrap`（`overflow-x:auto`），并按表头列数设置 `min-width = 列数 × 92px`；单元格 `white-space: nowrap`，窄屏改为横向滚动而非挤压。

### 6. 修复线上存活 BUG：`list | list` → `TypeError`
**文件**：`cloud_relay_v2.py`（"新设备加入已有组"广播分支）
```python
- for w in list(group.pcs) | list(group.phones):
+ for w in list(group.pcs | group.phones):
```
`group.pcs / group.phones` 是 `set`，先 `list()` 再 `|` 必然抛 `TypeError`。该分支在"PC 已在线时手机接入"这一最常见路径上触发，导致新设备加入通知发不出去、分支后续逻辑被整体跳过（线上 ERROR/Traceback 均可观察到）。

### 7. 手机搜索加防抖（附带）
**文件**：`dashboard.html` · `phoneSearchDebounce()`
**改前**：`oninput="loadPhones()"` 每按一键就全量请求一次（通话页早有 500ms 防抖，两页行为不一致）。
**改后**：统一 400ms 防抖，降低服务端压力，也减少撞上 60/min 限流的概率。

### 8. 登记页 / 人员页补 401 提示（附带）
`loadVisits()`、`loadPins()` 原用原生 `fetch`、不看状态码；现命中 401 时显示横幅 + "登录已过期"表内提示。

## 三、未覆盖（建议下一批）

1. **自动刷新冲掉正在输入的内容**：`refreshAll()→showPage()` 每 15 秒重建整表/整图，内联编辑中的姓名会被重置，且无"暂停自动刷新"开关（优先级最高）。
2. **无 URL 路由**：F5 回到首页，高频页面每次刷新都要重走导航。
3. **可读性**：表头与次要文字 11px、次要色对比度约 4.1:1，未达 WCAG AA。
4. **效率摩擦**：改管理员密码需手输数字 ID；删除仍用原生 `confirm()`；人员管理有空"操作"列；"详情"按钮只弹 Toast。
5. **原生 fetch 页面**（`loadAdminAccounts`、`loadPinDropdown`、`loadCallDeviceOptions`）尚未纳入统一请求层。
