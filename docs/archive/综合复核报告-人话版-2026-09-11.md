# 综合复核报告（人话版）—— 2026-09-11

> 这份是给老板审阅用的"说人话"版本。技术细节都在《综合复核报告-2026-09-11.md》里，这份只讲"员工/你会在什么时候、遇到什么麻烦"。

---

## 先说结论

这次更新（v4.19/v4.20）把管理面板上一批"看起来正常其实没连上/没保存/没导全"的问题修好了，实测通过。

但我把所有端的代码又翻了一遍，发现 **3 件事现在正在发生**，比面板那些都急：

---

## 一、现在正在发生的 3 件急事

### 急事 1：办公室的"额度"被人抢光了，登记会被系统拦下

打个比方：云服务器给每个网络出口设了个"每分钟 60 次"的门槛。但你办公室所有电脑、所有手机在系统眼里是**同一个出口**，大家一起抢这 60 次。

- 每台装了插件的电脑，只要 CRM 页面开着，**每 5 秒自动发 1 次查询**（在问"有没有新手机要配对"）——一台就是每分钟 12 次。
- 5 台电脑就把 60 次用完了；你们 20 个人用，理论上要 240 次/分钟，超了 4 倍。
- 管理面板就算没人登录，也还在每 15 秒刷一轮（全在白白发请求）。

**真实发生的**：今天下午 16:54，有员工做"上门登记"的请求被服务器直接拒绝（429）——这是真实业务被打断，不是猜测。

**员工感受到的**：拨号失败、登记失败，一会儿好一会儿坏，像是服务器抽风。其实是自己人把额度抢光了。

**怎么修（都不用员工多做任何操作）**：把登记/拨号这类正常业务的门槛放宽；插件那个"每 5 秒问一次"改成 30~60 秒问一次；面板没登录时别再瞎刷新。

### 急事 2：面板"通话记录"页面永远是空的——手机端压根没上报

面板新做的"通话记录"功能本身是好的，但查了生产库：**通话记录 0 条、行为日志 0 条**。

翻代码找到了三个卡点：

1. 有一段"记录手机行为日志"的代码，**写了但从来没人调用它**（等于装了根管子但没接水龙头）——所以行为日志必然是 0。
2. "通话记录上报"有个前提：手机必须跟服务器"握手成功在线上"才肯传。很多手机连不上/在等授权，就永远不传，而且**不报错、没提示**，看起来一切正常。
3. 还有个"记住上次传到哪"的标记，如果手机以前连过别的服务器，这个标记会让它以为"都传过了"，再也不传。

**怎么修**：把没接上的线接上；传不出去时至少在手机上提示一句；这个"标记"要么跟服务器绑定，要么给个手动重置。另外，有些手机通话记录几千条，现在的传法是从**最老的**开始一条条传，要传好几天才轮到"今天"——顺序要反过来。

**你先帮我确认一件事**：查一下库里 `phone_daily_stats` 是不是也是 0。如果是，就坐实了"握手不成功就不传"这个原因，修起来方向就定了。

### 急事 3：手机管理页里 101 台"设备"，100 台是假的

上次压测脚本不小心把数据打进了正式数据库（100 条名为 ZZLOADTEST 开头的假设备）。现在管理页里真设备就 1 台，其余全是假的，没法按这个判断真实情况。

**需要你拍板**：确认后我先备份数据库再删这 100 条。以后压测脚本强制走独立测试库，绝不再碰生产数据。

## 二、各端还有哪些坑（按员工每天遇到的程度讲）

### 手机端（20 个员工）

| 场景 | 会发生什么 |
|---|---|
| 换了服务器、在列表里点"设为当前" | 界面高亮了新服务器，**实际还连着旧的**，拨号指令发不出去，排查半天 |
| 手机电量优化/后台被系统杀了 | 自动重连的"定时器"跟着进程一起死了，没人再尝试重连，第二天上班拨号全失灵，只能手动开 App |
| 统计页点"同步" | 如果云端暂时没有数据（比如 PIN 没注册），会**把手机里存的上门记录直接清空**，提示还只是"云端暂无记录" |
| 点了"手动断开" | 重开 App 就自动重连上了，"手动断开"形同虚设 |
| 通话记录页点"立即拨号" | 走的是系统直拨，**双卡手机永远用默认卡**，跟电脑点号的选卡行为不一致 |
| 双卡手机换过卡 | 拨号可能打到错的卡上，用户没任何感觉 |
| 部分小米双卡机型 | 该自动点的系统选卡弹窗没人点，要手动点一下（其他机型没这问题） |

### 电脑端（坐席用，主力是 Electron 版）

| 场景 | 会发生什么 |
|---|---|
| 手机和电脑同一 WiFi，选"局域网优先" | **永远连不上**——电脑端为了安全只在自己"本机"上开门，手机的局域网连接进不来；而手机端还在提示"请检查电脑防火墙"，按提示查是白费功夫。这是全端最误导人的一个 |
| 工具突然自己消失 | 电脑端程序遇到任何"没接住的错误"会直接退出，没有提示，坐席只能重启 |
| 手机刚掉线那几分钟 | 电脑界面还显示绿点"已连接"（最长要 2 分钟才变灰），这时候拨号必失败，员工会反复点 |
| 手机关掉再连 | 旧连接断开的"遗言"会误杀新连接，手机显示在线、电脑显示离线，拨号排队 30 秒超时，只能强制重连 |
| 发短信手机没收到指令 | 短信窗口**永远卡在"等待手机确认…"**，不知道发没发出去 |
| 设置里勾了"开机自启" | 这个开关是**假的**（勾了、显示了、注册表根本没写），重启电脑软件不会自己开 |
| 选了"关闭即退出" | 其实没退干净：主窗没了、托盘图标也没了，程序还挂在后台 |
| 翻页时复制东西 | 每次拨号都会抢你的剪贴板 |
| 电脑半夜网络抖了一下 | 重试 30 次后彻底躺平，第二天白天也不会自己恢复，要手动重启 |

### 浏览器插件（坐席每天高频用）

| 场景 | 会发生什么 |
|---|---|
| 换了个人用电脑/CRM 改版导致检测方式退化 | 检测到的"新坐席号"只存了一半，**拨号和登记还是挂在上一任顾问名下**——客户串号，业务归属错，这个要优先修 |
| 页面上"拨打"链接点了没反应/拨错人 | 链接的点击动作只绑了第一次检测到的号码，页面切换客户后这个链接**还在拨上一位客户的号** |
| 手快连点两下"拨打" | 真的会拨两次；而且电脑端拒绝时插件不吭声、偷偷再从云端拨一次 |
| CRM 页面里嵌套的小窗口里点号 | 点了**没有任何反馈**（成功失败都看不到），只能反复点 |
| 云端短暂无响应 | 授权弹窗、同步会**永久卡住**（有 3 处请求没设超时） |
| 一次同步几百条记录 | 几百个请求同一时间发出去，直接把办公室的额度打爆（跟急事 1 是一伙的） |

### 管理面板（你自己用）

已修好的那批没问题了，还剩：

- **时间可能差 8 小时**：服务器时间和浏览器时区没对齐，"今日统计"的边界可能不准（先查服务器时区再决定改不改）。
- **管理员令牌/密码放在网址里**：token 会进浏览器历史和地址栏；登录、加账号、改密码的密码也是放在网址里传的——建议改成不进网址的方式，**不增加任何操作**。
- **刷新会打乱你的操作**：通话记录翻到第 N 页，15 秒后被弹回第 1 页；筛选条件被重置成"全部"；展开看了一半的详情被折叠。
- 小毛病：人员管理有个空白的"操作"列；手机"详情"按钮点了只弹一句话；改密码要手输数字 ID；删除还是老旧的确认框；F5 刷新回到首页。

### 云端服务器（你的私有云）

- 一次大查询或"导出全量 CSV"期间，**所有人的拨号指令会卡住几秒**（数据和界面展示都挤在一根管子上）。
- 某条登记在推送瞬间手机恰好掉线，这条数据**无声无息地丢**（既没送到，也没进"待补推"名单）。
- 别人只要知道某个员工的配对码，就能拉走他的全部来访记录（含客户手机号），没有次数上限——你们内部用风险可控，但修起来一行都不难。

## 三、安全方面：不费劲就该做的（都不影响员工使用）

1. **改掉 123456 口令**（5 分钟）。
2. **服务器的 9001 管理口收回**——它现在对全网开着，而且密码跟你 SSH 密码是同一个，这是最危险的一条；8090 面板同理。改成只允许你常用 IP 访问，或走 SSH 隧道（10 分钟）。
3. 登录/改密码/加账号改 POST，密码不进网址（员工无感）。
4. 手机 App 关闭"系统备份带走 PIN 和客户资料"（一行配置）。
5. 各端日志里的配对码、短信内容打个码（防止日志外发时泄密）。
6. 中长期：给云端加 HTTPS（员工无感，需要点部署工作）。

## 四、我建议的动手顺序

**第一批（这周，止血）**：① 急事 1 限流治理 → ② 急事 2 通话上报（先查那个表确认原因）→ ③ 急事 3 清理假设备（等你点头）→ ④ 登记"无声丢失"补上 → ⑤ 电脑端"一点小错就退出" → ⑥ 同步不清空手机数据 → ⑦ 插件"串号"和"拨错人" → ⑧ 插件双拨。

**第二批（下周，顺不顺手）**：局域网直连二选一（建议干脆承认只走云端，把误导文案和无效选项清掉）；换服务器自动重连；后台保活；授权时不误踢正在用的手机；云端大查询不卡全员；面板凭据出网址+刷新不打乱操作。

**第三批（慢慢来）**：时间时区、面板小毛病、插件其余项、手机端其余项、Go 版要不要继续发布（现在连编译都过不了，不发布就归档）、安全收尾。
