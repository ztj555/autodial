## 一、P0 致命问题（9 项，均已核验）

### 云中继

**PY-P0-1 ✅ `:memory:` 降级路径完全失效，且漏建 4 张表** — `cloud_relay_v2.py:211-239`
主 DB 初始化失败后 `DB_PATH=':memory:'`，但 `sqlite3.connect(':memory:')` 每次返回全新空库：`init_db()` 建完表就 close，此后所有 `_connect_db()` 拿到的都是无表空库 → 全部 REST API 500、设备授权全部拒绝。降级分支漏建 `phones / call_records_raw / phone_events / phone_daily_stats` 4 张表（`pin_groups` 已建，L221 `create_groups`；`ALTER TABLE phones ...` 静默失败可证）。

> 注：原报告误写"漏建 5 张表（含 pin_groups）"，经全量复核修正为 4 张。

### Chrome 扩展

**EX-P0-1 ✅ auth.html 全部逻辑为内联 JS，被 MV3 默认 CSP 阻断，设备授权流程整体死亡** — `auth.html:126-189`
两段内联 `<script>`（132、151 行）与内联 `onclick` 全部被 MV3 CSP（`script-src 'self'`）拦截。弹窗能打开但按钮无反应、数据永远显示 "-"。**README v4.14 宣称的"扩展授权弹窗携带 PIN"修复实际无法到达运行态**。修复只需抽成外部 `auth.js`。

### Go PC 端

**GO-P0-1 ✅ Origin 校验可被绕过，且比原判定更严重（v4.14 S1 修复无效）** — `security.go:32-43`
两重绕过：① 空 Origin/`null` 直接放行（L32-33），`<img src="http://127.0.0.1:35432/dial?number=...">` 这类 no-cors GET（不带 Origin）即可静默拨号；② `strings.HasPrefix(o, "http://localhost")` 前缀匹配无字符边界校验，`http://localhost.evil.com`、`http://127.0.0.1.attacker.com` 均通过 → 恶意网页可静默调用 `/dial`、`/sms`、`/api/set-pin`（接管设备映射），且 `/dial` 不校验 HTTP Method（GET 即触发）、响应带 `Access-Control-Allow-Origin: *` 可被读取。
> 注：原报告仅提前缀绕过，未提空 Origin 放行；全量复核确认此条严重性被低估。

**GO-P0-2 多 goroutine 并发写同一 WebSocket 连接（gorilla 明确禁止，可 panic）** — `server.go` / `cloud.go` / `app.go`
至少 4 处违反单写者约束：本地 WS 读循环写 pong/auth_ok 与 `sendToPhone` 的 `WriteJSON` 并发；云 WS 读 goroutine 无锁写与持锁的 ping ticker 并发；`sendToPhone` 写 `devices[].CloudWs` 完全无锁。帧交错可致随机崩溃（手机 ping 期间用户拨号即常见触发条件）。

**GO-P0-3 ✅ 云通道 ACK 无人处理，云发送必然 6 秒超时并引发重复拨号** — `cloud.go:155-210`（switch 缺 `case "ack"`）
手机经云中转回的 ACK 被静默丢弃（只有本地 WS 的 `handleLocalWS` 处理 ack，server.go:470）→ 云通道每次发送等满 2×3s 超时误报失败 → `/dial` HTTP 响应挂 6 秒 → `SendDial` 误判失败写入 `dialQueue` + 发 `reconnect_request` → 手机重连后**同一号码拨打两次**。

### Electron PC 端

**EL-P0-1 ✅ 云中继多服务器 failover 完全失效：generation 计数器双重递增** — `cloud.js:119、305、321`
`connectFromList()` 第 305 行 `++_cloudTraversalGeneration` 捕获本代标识，但其调用的 `connect()` 内部（119 行）再次自增同一全局变量 → 回调里 `thisGeneration !== _cloudTraversalGeneration` **恒成立**，`tryNext(index+1)` 永不执行。多服务器配置只有第一台会被尝试，settings.html 承诺的"自动遍历连接"是虚假功能。

**EL-P0-2 ✅ HTTP/WS 只监听 127.0.0.1，局域网直连（LAN 模式）整条链路失效** — `main.js:835`
`server.listen(PORT, '127.0.0.1')`，而 UDP 发现广播（discovery.js）仍向局域网宣告 `LOCAL_IP:35432` → 手机连接必 refused；`server.js` 的 Host 白名单与 `verifyClient` 也会拒绝手机来源。LAN 握手、UDP 唤醒、防火墙入站规则全部成为死功能。若收窄为本机服务是有意为之，则 LAN 相关代码应整体移除。

### Android 端

**AN-P0-1 ✅ 签名密钥密码硬编码且 debug 复用 release 签名** — `app/build.gradle:18-36`
`storePassword ... ?: 'RongXin2026!'` 明文写死；debug 构建同样使用 release 签名。拿到仓库者可签同签名恶意 APK 冒充升级（Android 允许同签名覆盖安装）。供应链最高级别风险。

**AN-P0-2 ✅ `registerScreenOnReceiver` 缺 EXPORTED 标志，Android 14+ 必抛异常并连锁崩溃** — `DialService.kt:548`
targetSdk 34 下运行时注册 receiver 必须指定 `RECEIVER_EXPORTED/NOT_EXPORTED`，此处用两参版本 → Android 14 上 `DialService.onCreate` 必抛 SecurityException 进入 catch 恢复路径，连锁产生：WakeLock 泄漏 ×2、TelephonyCallback 重复注册、亮屏健康检查失效。
> 注：原报告的"云同步可能丢失"子项经复核不成立——`startDataSync()`（L297）在异常点（L317）之前已执行，同步任务已投递。

## 三、P2 一般问题（61 项，按端列要点）

**云中继（12）**：多处 `int()` 未捕获 ValueError（`/api/logs`、`/api/v1/calls`、`/api/v1/events`、`/api/v1/stats/report`）导致该连接请求失败（websockets legacy 的 handler 有 `except Exception` 包裹，不会崩服务器）；`/api/v1/visit` 把顾问电话号 upsert 进 `advisor_names.name` 与 CRM 姓名互相覆盖；WS 版 `auth_response` 缺 PIN 归属校验（与 REST 版不对称）；限频按 IP 且成功握手也计数（NAT/重连风暴误伤）；离线 visit 为每个 PIN 创建永不回收的空 PinGroup（缓慢泄漏）；批量导入 GET URL 传 200 条 JSON 易超 URL 上限；`/api/v1/auth/pending` 无鉴权泄露 default_pin；发送失败只 discard 不清 meta；Docker entrypoint 用 `except KeyboardInterrupt` 捕 SIGTERM（永不可达）导致 docker stop 丢统计（最多丢 5 分钟，有 300s 定期快照兜底）；Docker 模式 `load_stats()` 永不执行；**websockets 依赖未锁定（原 PY-P0-2 降级）**：`requirements.txt` 与 Dockerfile 的 `websockets>=12.0` 无上界，Dockerfile 中 `>` 被 /bin/sh 解析为输出重定向（生成垃圾文件 `=12.0`），实际安装最新版——`websockets.legacy` 经实测（12.0/16.0/16.1.1）与官方 changelog 确认从未移除（14.0 弃用、15/16/17 均保留），故**不会 ImportError**，但使用已弃用 API 且版本未锁定，未来版本存在移除风险，建议钉死 `websockets>=12,<14`。
> 注：原报告"REST 的 `x-autodial-pin`/`authorization` header 大小写敏感（OkHttp 首字母大写会 401）"一条经实测确认为**误报**：websockets 的 `Headers` 内部键全部小写（`dict(request_headers)` 后 `.get('x-autodial-pin')` 对任意大小写均命中），已从本清单移除。

**Chrome 扩展（9）**：5s 授权轮询用 setInterval 而非 chrome.alarms（MV3 SW 休眠后不可靠）；拨号/挂断/登记 fetch 无超时（与 README"500ms 超时"不符——仅 ping 有）；`lookupKidFromCrm` 无精确匹配兜底取第一个（登记挂错顾问）；`escHtml` 不转义引号 → `<option value="...">` 属性注入仍在；右键菜单 document 级 mousedown 监听器累积泄漏；清除 PIN 后被页面自动"复活"；`host_permissions: <all_urls>` 过宽且掩盖 `tabs.query` 依赖；all_frames 注入 + subtree MutationObserver 性能放大；chrome.alarms 0.25 分钟被 Chrome 120+ 钳制为 30s。

**Go PC 端（15）**：map 迭代顺序随机 + 前端字符串对比 → **手机列表每秒重绘、重命名输入框被销毁（多手机时重命名基本不可用）**；adapter 把 dial-sent/error 伪装成 dial-result → 每次拨号成功都追加"号码 ✗"错误日志；udp.go 裸读全局 pinCode 绕过 pinMu（data race）；activePin 多处锁外读；读锁下写共享结构；logger 压缩先删源文件后 flush zip（可能永久丢日志）；connectCloudServer 修改全局 DefaultDialer；云状态变量群无锁；重连循环在 `pc_auth_ok` 前判 connected → 多服务器配置最终只有最后一台存活（有前置条件：服务器响应慢于 2s）；`UpdateSettings` 不重置 cloudUserDisconnected → 关云再开云后**永不自动重连**（限定连接建立失败场景）；RestartApp 新旧实例端口竞争；全局 Enter 键在 SMS 弹窗/重命名框中意外触发拨号；主题持久化因脚本加载顺序失效（重启退回默认）；4 位 PIN 无速率限制可穷举；WS 写全部无 SetWriteDeadline（对端假死可拖死全局，仅 TCP 缓冲耗尽时）。
