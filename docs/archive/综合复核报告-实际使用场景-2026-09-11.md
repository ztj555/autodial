## 一、一句话结论

上轮问题修掉了约一半：**管理面板那批基本清零**，Android 的离线队列 / 去重也修好了。但：

1. 真正会"天天出事"的头号问题——**REST 限流按 IP 60/分钟**——上次只是把提示改清楚了，**口径没改**，线上已经真实拦过员工的上门登记（9-11 16:54 日志）；
2. 本轮新发现 3 个高影响问题：**Android 14 前台服务权限缺失**（新手机后台保活/开机上线失效）、**面板批量导入超过约 20 行必失败**、**手机没连上却显示"已拨出"**；
3. **局域网直连自始至终是死的**（PC 只监听 127.0.0.1），手机上还留着"检查防火墙"的误导提示，建议直接砍掉入口，别再修。

## 四、按真实场景走一遍

### 场景 1：早上 8:50，全公司同时开工（**最严重**）

- 每个坐席的 CRM 页面开着 → 扩展每 5 秒请求一次 `/api/v1/auth/pending`，一台电脑 **12 次/分钟**；
- 20 台电脑走同一办公室出口 IP → **240+ 次/分钟**；
- 服务器规则：同一 IP 每分钟最多 60 次（`cloud_relay_v2.py:567,570-579,1442`）；
- 第 61 次开始，**同一时刻所有人的拨号、登记、手机上报全部返回 429**；
- **这不是推测**：9-11 16:54 的真实日志里 `/api/v1/visit`（员工上门登记）和 `auth/pending` 已被 429 拦下；管理面板自己的 15 秒刷新也在持续消耗这个额度。
- 结论：这是当前第一号问题，且不修的话"20 人一起用"必中。

### 场景 2：坐席一键拨号

1. 浮窗点"拨号" → 扩展先问本机 PC；
2. **手机没连上 PC** 时 PC 回 `200 {success:false, error:'手机未连接'}`（`pc-app-Electron/modules/server.js:154-164`）；
3. 扩展只判断 HTTP 是否成功（`AutoDial-Extension/background.js:220-224`）→ 浮窗显示"✓ 已拨出"，**实际没拨，也不会再走云端兜底**；
4. 即使拨号成功，5 秒后的自动心跳会重写浮窗内容，若这次拨号失败，**红色失败提示最多存活 5 秒**就被冲掉；
5. 快速双击浮窗会发两次拨号请求（无冷却/无锁）；
6. 挂断同理：PC 返回 `success:false` 也显示"已挂断"（`background.js:476-478`）。

### 场景 3：员工在手机上登记 / 看统计

1. 点"同步"以云端为准 → 若云端因限流、PIN 未注册、库被重置等原因返回空，**本地 `visit_records` 被整段清空**（`StatsFragment.kt:541-559`），还顺手清掉 `registration_timestamps` 和尚未补推的离线记录；
2. 首次连接失败时，界面停在"连接中"，按钮一直是"取消"（`ConnectionManager.kt:887-895`、`DialService.kt:314-316`），员工不知道是没连上还是还在连；
3. 云端重连只重试 8 次（约 40~70 秒）就永久停止（`ConnectionManager.kt:117-118`），服务器夜间重启、地铁/电梯断网后，手机不会自己再上线，除非员工主动开 App 或亮屏。

### 场景 4：管理员在面板维护

1. 导出、登录过期、刷新冲输入、密码明文等问题已修好；
2. **批量导入**：选了 200 行→前端打包 200 行进 URL（`dashboard.html:2058-2068`），而 websockets 服务器对 HTTP 请求行有 8192 字节硬上限，中文转义后约 **20 行就超**，第一批就被拒，页面只报"网络错误"；
3. 设备名由手机自报（`phone_hello` 的 `deviceName`，无字符校验），管理员点"详情"时它被拼进 `toast` 的 `innerHTML`（`dashboard.html:1106-1110,1559-1560`）——恶意设备可借此偷管理 token；
4. 趋势图按 UTC 日期分桶、列表按浏览器本地时间显示，若服务器时区不是 +08，看到的时间会整体偏移（需先确认服务器时区）。

### 场景 5：换人 / 换号（PIN 变更）

1. 坐席在 PC 上改 PIN：程序只记住了新 PIN 并刷新界面（`main.js:336-348`），没有通知云端，云中继仍把电脑放在**旧 PIN 组**（`pc_hello` 只在 WS 打开时发一次，`modules/cloud.js:148-151`）→ 新 PIN 的拨号、手机上线消息送不到电脑，直到重启云连接；
2. 扩展里，CRM 改版导致精确选择器失败时走兜底识别：`self_phone` 更新为新坐席号，但 `getPin()` 仍优先返回旧 `pin`（`background.js:176-178,520-538`）→ **拨号与登记都记在前一任顾问名下**（业务风险）；
3. 管理员改密码/账号相关操作目前要手输数字 ID，容易填错（面板 P1）。

### 场景 6：低频但必然遇到

- **授权踢真机**：新设备以非默认 PIN 连接需要授权，但代码先把这个 PIN 上正在正常使用的手机踢下线，再挂起等授权（`cloud_relay_v2.py:739-745` vs `748-780`）；若此时扩展不在线，直接拒绝，真机白掉线；
- **离线登记丢失**：手机在线时 `forward_to_phones` 内部吞异常且不落队列，手机在"判断在线"和"发送"之间掉线的那条登记**永远收不到**；补推时发送失败也会先删记录（`cloud_relay_v2.py:647-651,903-916,1399-1410`）；
- **通话记录从未上报**：生产库 `call_records_raw`/`phone_events` 一直 0 行（9-11 实测），面板与导出因此都是空表；这不是面板问题，是**手机/PC 上报链路**问题，需单独立项。

## 六、跨端主线（这 3 条不定，单点修了还会再犯）

1. **"限流"按 IP 分蛋糕，但全公司共用一扇门。**
   第一次限流改造（v4.15）把 `phone_hello`/`pc_hello` 改成 IP+PIN 维度，但 v4.18 新增的 REST 全局限流又退回按 IP。扩展轮询、面板刷新、手机上报全挤在一个桶里。**建议原则：认证类（login、PIN 尝试）严格按 IP；业务类按账号/PIN 或大幅放宽；高频轮询类单独放行或加缓存。**

2. **"状态显示"与"真实状态"不同源。**
   PC 首屏缺 `connected`、手机切服务器不重连、面板 429 只提示不退避、扩展"已拨出"靠 HTTP 码判断。**建议原则：界面上任何"连上了/成功了"必须来自真实结果（body/ACK/事件），首屏主动拉一次。**

3. **"局域网直连"承诺了但从未兑现。**
   PC 端 `127.0.0.1` 监听（Electron `main.js:830`、Go `server.go:260`），手机端却一直在试 `ws://<局域网IP>:35432`；UDP 还在广播局域网地址；提示还归因于防火墙。**建议（20 人规模）：直接砍。** 手机端删掉"仅局域网"策略/UDP 发现/防火墙提示，保留"自动（云）"即可，省掉一整类排查和文案维护。若你确实想省云流量，再单独立项让 PC 绑 `0.0.0.0` + 同子网配对放行。

## 七、安全专项（"不折腾"清单）

> 前提：内网 20 人、云端只有你维护。目标是在**不改变员工和坐席操作习惯**的前提下，堵住最值钱的口子。按投入从低到高排。

1. **换管理员密码**：现在口令是 `123456`（hash 可反推验证），且 4 位即可。
2. **把 9001（Supervisor）和 8090（1Panel）从公网收回**：现状 `0.0.0.0` 暴露，且 9001 口令与服务器 SSH 相同——**这一条比面板本身危险得多**。用 ufw 只放行你常用出口 IP，或走 SSH 隧道。
3. **面板 toast 转义**（D-1）：一行修复，堵住"恶意设备借管理员点击偷 token"。
4. **`docker-compose.yml` 端口改 35440**，避免哪天误启抢了生产 35430。
5. **Android `allowBackup=false`**：避免 PIN 随系统备份外流。

**B. 低成本、值得做（小时级）**

6. 登录改 **POST + 请求体**；token 从 URL 改 `Authorization` 头（对应 C-06/D-8）。
7. 口令哈希换 **PBKDF2/argon2**（登录时迁移即可）。
8. 给 35430 前置 **HTTPS**（Caddy/Nginx + 证书，或内部自签），域名比 IP 证书更方便；若不换域名，至少限定来源 IP。
9. **设备在 `phone_hello` 领 token**，客户数据端点（visits/visit/calls）校验 token 或至少 `pin+device_id`（对应 C-05）。
10. **删除仓库里的签名文件** `autodial-release.p12`、`android-app/autodial-release.p12`，并**更换签名密钥**（它已在 git 历史里）。（现在还未泄露到公开远端则风险有限，但内部仓库也应处理。）

**C. 需要你拍板（会略改习惯，收益明确）**
