# AutoDial 浏览器扩展

> MV3 | 最后更新：2026-09-15 | PC 直连优先 → 云端兜底 | 16 套色相 × 亮白 / 暗夜 | v6.3.4（挂断按钮空心常态 + 成功挂断后按钮留在原位）

坐席手机号即 PIN，打开 CRM 页面自动检测，无需登录，无需密码。

## 核心功能

1. **自动检测 PIN**：打开 CRM 页面 → CSS 选择器扫号 → 自动存为 PIN
2. **自动检测姓名**：同步抓取业务员姓名，无需手动输入
3. **双模路由**：Ping PC 直连（500ms 超时），不可达走云端 `/api/v1/dial`
4. **主题（16 色相 × 亮白 / 暗夜）**：色相与明暗是两个独立维度，右键菜单与弹窗「外观」卡片均可切换
5. **浮动按钮**：CRM 页面注入可拖动的拨号/挂断按钮
6. **右键菜单**：拨号/短信/登记/主题切换/手动拨号/设置/PC状态/PIN显示
7. **一键登记**：CRM 详情页识别姓名+手机号 → 确认弹窗 → 客户端提交 CRM + 云中继存储

## 文件说明

| 文件 | 角色 |
|------|------|
| `manifest.json` | MV3 清单，匹配 CRM 域名 |
| `background.js` | Service Worker：PIN 管理 + 双模路由 + 登记 API |
| `themes.js` | 主题唯一权威源：`AD_THEMES`（16 套 × light/dark）+ `AD_APPLY_THEME` 等 |
| `addr.js` | 云中继地址唯一权威源：`AD_ADDR`（候选池 / 探测 / 列表拉取） |
| `cs-00-core.js` | ① 核心工具层：`isTopFrame` / `isOwnUiNode` / `getMyPhoneAndNameFromCRM` / 图标表 / `escHtml` |
| `cs-10-theme.js` | ② 主题层：主题表 + `applyTheme` / `applyMode` + Toast + 挂件句柄 |
| `cs-20-widgets.js` | ③ 挂件层：浮动按钮 / 挂断按钮（含拖拽缩放）/ 手动拨号条 / 号码刷新与状态反馈 |
| `cs-30-menu.js` | ④ 菜单层：自定义右键菜单 / 菜单项文案刷新 / 主题选择子菜单 |
| `cs-40-dialogs.js` | ⑤ 弹窗层：设置弹窗 / 一键登记弹窗 / 区块与按钮辅助 / 桌面与短信操作 |
| `cs-50-biz.js` | ⑥ 业务层：实时取号（`refreshActivePhone`）/ 检测 PIN / DOM 就绪编排 / 后台消息监听注册 |
| `cs-60-iframe.js` | ⑦ 子 iframe：激活态判定 / 详情页号码与姓名提取 / 5 秒心跳上报 / 切客户即时刷新 |
| `cs-70-boot.js` | ⑧ 启动编排（**原 `content-script.js`**，v6.3 改名为模块名）：挂件与业务启动 / 跨页换肤 / 客户姓名接收 / 残留号码保鲜 |
| `popup.html` + `popup.js` | 弹窗：服务器配置 + PIN 设置 + 状态查询 + 顶栏刷新 |
| `auth.html` + `auth.js` | 设备授权弹窗（外部脚本规避 MV3 CSP） |
| `theme-init.js` | 弹窗 / 授权页的主题变量注入 |
| `icons/` | 扩展图标 (16/48/128) |
| `AutoDial-API.md` | API 参考文档 |

> **注入顺序有讲究**：`content_scripts.js` 数组 = `themes.js → addr.js → cs-00-core.js → cs-10-theme.js → cs-20-widgets.js → cs-30-menu.js → cs-40-dialogs.js → cs-50-biz.js → cs-60-iframe.js → cs-70-boot.js`。
> MV3 没有打包工具，文件之间不能 `import`，共享符号统一挂在 `window.__ADCS` 上，靠数组顺序保证先注册后使用。
> ⚠️ 加新模块必须排在 `cs-70-boot.js` **之前**。
>
> v6.3.1 起主文件由 `content-script.js` 改名为 `cs-70-boot.js`（纯改名，内容零改动），
> 拆分前那份 1879 行的 `content-script.js` 已不存在。

## 安装

1. Chrome 打开 `chrome://extensions/` → 开启"开发者模式"
2. 点击"加载已解压的扩展程序"
3. 选择 `AutoDial-Extension/` 目录

## 首次配置

1. 点击扩展图标打开弹窗
2. 设置云中继地址（默认 `101.34.65.254:35430`）：
   - **测试** —— 只验证连通性，不会保存；失败会告诉你具体原因（超时 / 端口被拒绝 / 服务返回 HTTP xxx / 该地址不是 AutoDial）
   - **保存** —— 唯一的保存动作，保存后来源徽标显示「手动」
   - **候选下拉** —— 点输入框右侧的 ▾ 展开候选服务器浮层（`position:absolute` 覆盖显示，不占面板高度）；点某一项只是填进输入框，仍需点「保存」才生效。当前生效的那台带「当前」标记
   - **从网络获取**（浮层底部）—— 从 Gist / Gitee 拉候选列表刷新浮层，**不会**自动切换你正在用的地址
3. 打开 CRM 页面 → 自动检测坐席手机号为 PIN

## 日常使用

- 打开 CRM → 自动检测坐席号 → 点击拨号按钮 → PC/云端自动路由
- PIN 状态在右键菜单底部可见
- 换号时打开 CRM 重新检测即可

## 拨号反馈

| 提示 | 原因 |
|------|------|
| `✓ 已拨出` | PC 直连成功 |
| `✗ PC已上线，请重试` | 云端发现 PC 在线，应切回本地 |
| `✗ 服务器不可达` | 云中继未启动 |
| `✗ 未检测到坐席手机号` | 请打开 CRM 页面 |

## 右键菜单

- **🎨 切换主题**：色相 16 套（天空蓝/暗金/冰蓝冷峻/深空紫/赛博朋克/极简白/毛玻璃/森林绿/活力橙/海洋蓝/蓝绿渐变/薄荷清新/珊瑚日落/薰衣草/暖光米色/圆润糖果）+ 亮白 / 暗夜两档明暗
- **📞 拨打 / 💬 发短信**：对当前检测到的客户号码操作
- **📝 一键登记**：CRM 详情页可用，自动识别姓名+手机号
- **🖥 打开电脑端主界面 / 📋 显示隐藏悬浮窗**：PC 端控制
- **📱 手动拨号**：弹出号码输入条
- **⚙ 设置**：修改 PIN / 云中继地址（挂件的「测试连接」同样只测不存；「获取候选」只刷新候选池）
- 底部显示 `👤 PIN: 138xxxx` + PC 在线状态

> v5.4 起「同步登记列表」（抓取 CRM 列表页批量同步到云端）已移除，页面右键菜单与 popup 按钮均不再提供该入口；「一键登记」仅针对当前打开的客户。
>
> v5.5 起主题切换有两个入口：① 本右键菜单的「🎨 切换主题」；② popup 底部常驻的「外观」色块卡片（点一下即换肤，并实时同步给已打开的 CRM 页面悬浮挂件）。另：「森林绿」已由墨绿深色改为清爽浅色（原 `bg #0E1810` 近乎纯黑，观感发闷）。
>
> v6.0 起主题拆成两个正交维度：**色相 16 套 × 明暗 2 档（亮白 / 暗夜）**。此前是 9 套主题各自钉死一个明暗，色相与亮度混在同一个列表里（亮·暗·暗·暗·暗·暗·亮·暗·暗），切换没有规律；且「极简白」的 `bg` 实际是 `#1A1A1A`（纯暗）。配色数据由 PC 端 `pc-app-go/frontend/themes/theme-data.js`（16 套 × 7 档）转录取两端档位，因此与手机端、PC 端在同一色相、同一档位下颜色一致。其他端存的 7 档明暗会自动折叠（`warm/mist/light → 亮`，其余 → `暗`）。storage：色相 `__ad_theme` + 明暗 `__ad_theme_mode`。

## 一键登记流程

1. 打开 CRM 客户详情页 → 自动识别姓名+手机号
2. 右键悬浮按钮 → 点击「📝 一键登记」
3. 确认弹窗 → 客户端提交 CRM + 云中继存储 → WS 推手机通知
4. 浮动按钮显示「✅ 已登记」

> 需云中继在线（端口 35430）。
