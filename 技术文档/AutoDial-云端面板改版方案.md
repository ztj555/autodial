# AutoDial 云端面板改版方案（实用主义版 v2）

> 定位：本方案**只改 `cloud-relay/python/dashboard.html`**（必要时带一点前端辅助），不改任何后端接口、不动主题色值。
> 前提共识：面板的主要使用者就是站长本人（唯一管理员），评判标准只有两条 —— **重要信息第一眼能看到**、**干一件事的点击数最少**。

## 一、先盘清：你每天打开面板，其实只为了三件事

| 场景 | 你真正想知道的 | 现在要几步 | 卡在哪 |
|---|---|---|---|
| **A. 现在能不能打电话** | 手机在不在线、是谁的、多久前还在 | 打开首页 → 看「当前连接 2」→ 不知道是谁 → 滚到页面最底部看客户端表 | 最该第一眼看到的信息被拆成 4 处，且不在首屏 |
| **B. 查一通电话** | 某号码打过没有、什么时候、多久 | 侧边栏 → 通话记录 → 手动输入号码 → 点「查询」 | 无「今天 / 昨天」快捷日期；号码不能一键复制；每次都要手点查询 |
| **C. 记一条上门** | 导入一批 / 补录一条 / 改错 / 导出 | 侧边栏 → 上门登记 → **先点日期才出数据** → 去筛选行最右边找导入导出 | 默认是空状态「请选择筛选条件」；高频按钮埋在筛选条件堆里 |

其余内容（运行时长、消息类型分布、系统日志）都是「出问题才看」的运维信息，却占了首屏黄金位。

## 二、P0 —— 首页从「运维仪表盘」改成「值班看板」

### 2.1 目标排布（自上而下）

1. **连接状态条**（新增，整条通栏）
   - 文案：`手机 2 台在线` + `张三 · 1分钟前` + `李四 · 12分钟前`；次行 `PC 1 台在线 · 离线 3 台（点开）`
   - 0 台手机在线时，整条换成红底 + `当前没有手机在线`
   - 离线设备折叠成一行，点开展开明细
2. **今日两数**：今日拨号 / 今日登记（保留现有两张卡，并排大字号）
3. **待处理提醒**（新增，有内容才出现）
   - `5 条登记未同步 CRM`（数据源：现成的 `/api/v1/visits?source=unsynced&page_size=1` 读 `total`）
   - `2 台设备离线超 1 小时`
4. **快捷入口三枚**：查号码 / 批量导入 / 导出今日（点击后跳到对应页并带上筛选条件）
5. **运维区（默认折叠）**：服务详情、连接数趋势、消息类型分布；标题为「查看服务详情」

### 2.2 具体改法与行号

| 项 | 位置 | 改法 |
|---|---|---|
| 状态条替换 hero 卡 | `dashboard.html:582-594` | 删掉 hero 卡（含那个与顶栏重复的「立即刷新」大按钮），换成连接状态条 |
| 「在线手机/在线PC」改用实时值 | `:1631-1636`（`loadDashboard` 里读 `/api/history` 快照的那段） | 改为用 `:1641` 已经取到的 `/api/clients`，按 `role` 现算手机数 / PC 数。**不新增任何请求** |
| 「最近活跃」卡 | `:614-618` | 并入状态条（名字 + 多久前），删掉这张卡 |
| 统计卡区 | `:595-619` | 5 张减到 2 张（今日拨号、今日登记） |
| 图表区 | `:620-629` | 移到折叠区内 |
| 最近连接客户端表 | `:630-634` | 上移到第 2 屏顶部；与状态条内容重叠，可只保留状态条 |

### 2.3 顺带修掉的两个真问题

- **重启后头 30~60 秒「在线手机/PC」恒显示 0**：现在读的是每 30 秒一次的快照（`:1631-1636` 有 `history.length > 1` 守卫，数据不足直接跳过赋值），而同一屏的「当前连接」是实时值 → 两个数字当场打架，你会以为手机没连上。改用 `/api/clients` 现算后自动消失。
- **最多滞后 30 秒**：同上，一并解决。

## 三、P1 —— 列表页提速（减少点击）

### 3.1 上门登记页

| 项 | 位置 | 现状 | 改法 |
|---|---|---|---|
| 默认空状态 | `:707` | 进页面就问「请选择筛选条件」，必须手动点一次日期才出数据 | 进页面默认按「今天」查询 |
| 快捷日期 | `:690-691` 筛选行 | 只有两个 `date` 输入框 | 加 今天 / 昨天 / 近7天 三个快捷按钮（后端已支持 `days=N`，见 `cloud_relay_v2.py:2747`） |
| 导入 / 导出按钮位置 | `:694-705` | 埋在筛选行最右边，需要横向扫过去 | 移到卡片标题右侧，成为固定主操作 |
| 翻页按钮样式 | `:709 / :711` | `class="btn btn-sm"` **漏了修饰类** → `.btn` 基类没有背景和边框，实际渲染成**两坨裸文字**，看不出能点 | 补成 `btn-outline btn-sm` |
| 分页文字色 | `:708` | `var(--text2)` 拼错（应为 `--text-2`）→ 颜色失效、回退成继承色，文字比设计更黑 | 改 `--text-2` |
| 空状态列数 | `:740` | 表头 4 列，空状态写 `colspan="5"` → 「暂无 / 加载中」居中偏移 | 改成 4 |

### 3.2 通话记录页

| 项 | 位置 | 改法 |
|---|---|---|
| 快捷日期 | `:663-664` | 同样加 今天 / 昨天 / 近7天 |
| 号码一键复制 | `:1918` 附近行渲染 | 号码格加复制按钮（复制后 toast 提示） |
| 「类型」列 | 同上 | 「未接」字样可点击 → 直接筛出未接（当前只有一个下拉框，选项里没有未接）——⚠️ **未实施**：后端无 `call_type` 参数 |
| 分页统一 | `:1938-1940` | 与其它列表统一成同一套外观 |

### 3.3 三张表的「设备ID」列（新增建议）

现在首页客户端表、通话记录表的第一/首列都是**设备ID（长串字符，被截断成 20 位）**，你根本认不出是哪台手机。

**改法**：统一显示**设备别名**（如「杨蕊的手机」），没有别名时才回退显示截断的 ID。别名在「手机管理」页可以直接填。
代价：通话记录、首页客户端两张表需要一次 `device_id → label` 映射（一次请求，可缓存），或让后端在返回里带上别名（更彻底，但要改后端）。

### 3.4 分页 / 控件一致性

| 页面 | 现在的外观 |
|---|---|
| 手机管理（`:1760-1771`，渲染在表体内） | 居中文字 `第 X / Y 页（共 N 台设备）` + 灰底方框「上一页/下一页」 |
| 通话记录（`:1938-1940`） | 胶囊样式 + 左右箭头 |
| 上门登记（`:709-711`） | 裸文字（因为漏了修饰类） |

**改法**：统一成一套（建议「第 X / Y 页 · 共 N 条」+ 胶囊箭头按钮），位置统一放在表格下方。

## 五、这次**不做**的（附理由）

| 项 | 为什么不做 |
|---|---|
| 安全响应头（CSP / X-Frame-Options）、CORS 收紧 | 面板是你自用、内网+固定 IP，改了只有维护成本 |
| `/api/v1/visits?pin=x` 单 PIN 查询鉴权 | 这是手机端同步的既定设计；要改得动后端，且会影响手机端 |
| chart.js 换国内镜像 + 断网提示 | 你天天联网，收益低于改动风险 |
| 死常量 `HEARTBEAT_TIMEOUT`、`last_message_time` 清理 | 不影响看和用，属于代码整洁 |
| `test_*.py` 挪进 `tests/`、旧 Node 启动器残留 | 同上 |

> 如果你希望其中任意一条纳入本轮，说一声即可。

## 六、验证方式（改完怎么确认没改坏）

1. 本地 `cloud-relay/dev.bat` 启动（改面板必须重启进程才会生效 —— `dashboard.html` 在模块导入时只读一次）。
2. 浏览器逐页点一遍：首页 → 手机管理 → 通话记录 → 上门登记 → 人员管理 → 设置。
3. 专项验证：
   - 把 `visits.db` 换成空库起服务 → 首页状态条应显示「暂无设备在线」（而不是空白或 0）；
   - 断开手机 → 状态条应在 15 秒内更新为「0 台在线」且变红；
   - 上门登记页打开即出「今天」数据；
   - 翻页按钮肉眼确认有背景框（不再是裸文字）；
   - 切换亮白 / 暗夜两种模式看一遍，确认没有颜色错位。
4. 全部通过再考虑推云端；**推送前先确认手机端不受影响**（本轮不碰任何接口，理论无影响）。
